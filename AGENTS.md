# Работа над Смаугом

Прочитай `AI_HANDOFF.md` и `README.md` перед изменением проекта.

## Назначение проекта

Смауг разрабатывается как персональный финансовый помощник одного владельца. Исходный код открыт; универсальный продукт, многопользовательский режим и поддержка чужих установок сейчас не входят в задачу. Не добавляй такую сложность без нового требования владельца. Не удаляй существующие механизмы только потому, что ими мог бы пользоваться кто-то ещё.

Приоритет — полезный повседневный инструмент: меньше ручной работы и перегрузки, больше понимания финансов. Для существенных идей предлагай обоснованные упрощения и альтернативы; рутинные задачи выполняй без продуктовой бюрократии.

## Единая версия приложения

Цель — вести здесь код рабочего Смауга, Apps Script, структуру и миграции D1, шаблоны конфигурации и инструкции. Персональные значения поступают из приватной конфигурации и рабочих хранилищ. Не создавай отдельную расходящуюся реализацию ради публичности кода.

Сейчас соответствие репозитория работающему экземпляру не доказано. Перед переносом сверяй нужные компоненты; не выдавай приблизительную локальную копию за production. Различай исходный проект, собранный артефакт, проверенный код и опубликованную версию. Само обновление документации не устраняет расхождения.

## Приватность перед публикацией

1. Не публикуй операции, остатки, доходы, долги, частные планы, переписку, сведения о людях, здоровье и привычках, банковские скриншоты, приватные URL или идентификаторы личных ресурсов. Токены, пароли, ключи и значения секретов также остаются вне репозитория. Не добавляй защищённые изображения, на публикацию которых нет прав.
2. Проверяй не только код: персональные сведения могут оказаться в промптах, комментариях, инструкциях для агентов, аудите, тестах, миграциях и примерах. Общий характер бота допустим; личный контекст загружается во время работы. Простая замена имени не делает реальные данные синтетическими.
3. Используй полностью вымышленные данные в тестах и примерах. Публичные миграции могут менять структуру и общие справочники, но не должны содержать персональные исходные записи или реальные значения по умолчанию.
4. До отправки в любую публичную ветку проверь все исходящие коммиты, diff, новые файлы и добавляемые артефакты. Используй доступную проверку секретов и просмотр содержимого: сканер ключей не подтверждает отсутствие персональных данных. Не коммить рабочие выгрузки D1, копии личной таблицы, логи или резервные архивы.
5. `.gitignore`, папка `private/`, отдельная ветка и статус draft не делают опубликованные файлы закрытыми. Проверка в CI после push не заменяет проверку до публикации. При переносе существующего проекта учитывай его Git-историю, а не только последние файлы.
6. Те же правила действуют для сообщений коммитов, PR, issues, CI-логов, отчётов и вложений. Публичные проверки выполняются на синтетических данных без доступа к рабочей финансовой базе.
7. При обнаружении чувствительных данных останови публикацию затронутого материала и сообщи владельцу приватно категорию и расположение, без значений. Для уже опубликованного секрета подготовь его отзыв или замену; удаление из последнего файла не удаляет историю. Не переписывай историю и не меняй рабочие ключи без согласованного действия.

## Завершение изменений

После каждого изменения кода обнови `AI_HANDOFF.md` и `CHANGELOG.md` в том же коммите: фактические возможности, ограничения, проверки и статус выпуска. Не переноси в эти документы личную историю из чата. В документации используй `N ₽`, `<счёт>`, `<дата>`; в исполняемых тестах — вымышленные значения.

Для изменения структуры базы добавляй новую миграцию, не переписывая применённые. Проверяй затронутый сценарий целиком и защиту от повторной финансовой записи на тестовых данных. При изменении только документации не запускай команды с доступом к рабочим сервисам.

Для выпуска фиксируй связь с коммитом Git и совместимой схемой. Код, данные и резервные копии имеют отдельные версии; не объявляй восстановление проверенным по одному лишь наличию файлов. При сомнении о приватности покажи владельцу конкретный материал в закрытом канале до его публикации.
