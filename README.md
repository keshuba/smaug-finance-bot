# Смауг — личный финансовый бот для Telegram

Публичная основа финансового помощника. Бот работает на Cloudflare Workers и хранит записи в отдельной базе D1 **каждого владельца**. В этом репозитории нет чьих-либо остатков, долгов, платежей, банковских реквизитов, токенов, личных планов или копии рабочей базы.

Смауг говорит как ироничный хранитель казны: прямо предупреждает о риске перерасхода, но решение остаётся за владельцем. Арифметику делает код, а не языковая модель.

## Что работает

- Сообщения «купила шампунь за 500» и «получила 1000» создают запись, когда понятны сумма, счёт и категория. Недостающие данные бот спрашивает перед сохранением.
- «Сняла 5000 на психолога» записывает перевод с дебетовой карты в наличные, не расход. Если карта не названа и нет настроенной карты по умолчанию, бот спросит её.
- `/remind` добавляет ежемесячный платёж прямо в чате, `/reminders` показывает действующие напоминания, `/remind_off номер` отключает правило. Бот напоминает за 3 дня, накануне и в день платежа; для 29–31-го числа короткого месяца берёт последний день месяца. Эти платежи учитываются при оценке покупки и в плане.
- «Хочу купить книгу за 800» и `/buy` оценивают покупку по доступным дебетовым деньгам, известным платежам и утверждённому лимиту. Кнопки «Покупка совершена ✅» и «Отмена» управляют записью.
- `/treasury`, `/plan`, `/debts`, `/history` выводят картинки; версии с `_list` дают текстовые списки. Если создание картинки недоступно, бот отправляет список.
- `/history` показывает расходы за день, неделю и месяц, категории и цветную диаграмму.
- На вопросы о лимите дня, недели и периода бот отвечает обычным сообщением: сначала сумма, которую можно потратить сейчас, затем короткое пояснение недельной части и общего бюджета. Неистраченные деньги не добавляются к следующей неделе автоматически.
- Утреннее сообщение и вечерний вопрос, если за день не записано расходов. Напоминания о платежах приходят за три дня, накануне и в день платежа. Время настраивается в Worker.
- Повторная доставка Telegram не создаёт повторную финансовую запись: у операций уникальный ключ источника.

## Что пока не реализовано в публичной основе

Редактирование счетов, долгов, лимитов и разовых платежей через чат; переводы между своими счетами, кроме снятия наличных; частичная оплата долга; банковская синхронизация; Google Sheets; Apple Calendar; внешний ИИ и свободные консультации. Эти функции нельзя считать работающими только потому, что они обсуждались для личной версии. Текущая обработка текста основана на правилах и уточнениях.

Бот не видит банковский баланс в реальном времени. Начальный остаток и операции нужно сверять. Он не должен считать ожидаемые доходы и возвраты уже доступными деньгами. Лимит на текущие покупки включает продукты, кофе, косметику и подобные траты; известные обязательные платежи планируются отдельно. Если недельная часть исчерпана, необходимый расход требует явного пересмотра распределения.

## Запуск своей копии

Потребуются личный Telegram-бот, аккаунт Cloudflare и Node.js. Не используйте имя или токен существующего чужого бота.

1. Скопируйте `wrangler.example.jsonc` в `wrangler.jsonc`. Создайте свою D1-базу и впишите её ID в конфигурацию. `wrangler.jsonc` исключён из Git.
2. Выполните `npm install`, затем `npm run db:remote`. Миграция создаст **пустые** счета, долги и бюджет, но добавит общий справочник категорий.
3. Настройте свои счета через D1. В `examples/initial-data.sql` есть пример с нулевыми остатками. Перед применением укажите реально сверенные остатки, валюту и дату. Начальный остаток не записывайте повторно как доход.
4. В Cloudflare добавьте секреты `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `TELEGRAM_OWNER_ID` (числовой Telegram ID владельца). Секрет для webhook может быть случайной строкой из `A-Z`, `a-z`, цифр, `_` и `-`, длиной 1–256 символов.
5. Укажите `OWNER_NAME`, `TIME_ZONE`, `BASE_CURRENCY` и часы сообщений в `wrangler.jsonc`. Это настройки только вашей копии. Создайте подтверждённый `budget_periods` и нужные разовые `scheduled_payments` в своей D1. Добавьте один счёт наличных. Для карты, с которой обычно снимаете деньги, можно записать её числовой ID в `settings` под ключом `default_cash_withdrawal_account_id`.
6. Запустите `npm run deploy`. Зарегистрируйте адрес Worker как webhook у Telegram с тем же секретом. Для этого можно запустить `npm run webhook`, передав скрипту через окружение `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `WORKER_URL`. Скрипт не печатает токен.
7. Напишите своему боту `/start`. Проверьте `/treasury_list`, затем тестовую операцию на вымышленных данных. До внесения реальных денег проверьте, что все категории и счета определяются верно.

Для изображения нужен Browser Rendering binding `BROWSER`; его доступность и тариф зависят от условий Cloudflare. Без него списки продолжают работать.

## Хранение и приватность

Владелец задаётся секретом `TELEGRAM_OWNER_ID`; Worker принимает только личный чат этого аккаунта и проверяет заголовок webhook Telegram. Сообщения других людей игнорируются. Реальные данные лежат в вашей D1, не в этом репозитории. Не добавляйте сюда SQL-экспорт, скриншоты банков, локальные `.env`, `.dev.vars`, `wrangler.jsonc` с ID вашей базы или личные правила.

Долги, счета, разовые обязательства и лимиты пока создаются через D1. Ежемесячные платежи можно добавить через `/remind`. Если разовый платёж совершен, его статус нужно обновить вручную, чтобы бот не вычел его из прогноза повторно. Напоминание само по себе не доказывает оплату. При повторной сверке счёта запишите в `balance_transfer_id` последний уже учтённый перевод, чтобы не прибавить его к новому остатку ещё раз.
